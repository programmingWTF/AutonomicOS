## M5 🚧 Action 通道（CHARTER §1.5 的灵魂）

**核心洞察（写进代码注释了，也是整套设计的立身之本）：**
"AI 掌握底层"**不等于给 AI 一个 root shell** —— 那不是赋权，是等一个坏天气出事。
真正的做法是给它一条**比 shell 更有强制力**的通道，因为有约束所以才有力量。

架构（清晰的权限边界，两个守护进程）：
```
autonomic-agentd  uid=autonomic + ProtectSystem=strict —— 能思考，碰不到世界
        │  unix socket 0660 root:autonomic
        │  连上先查 SO_PEERCRED，请求字节还没解析就可能被拒
        ▼
autonomic-actd    root，但只认 4 个登记过的原语 + 4 个可写前缀
```

三个阶段，每个 action 必须回答三个问题而不是给一个承诺：
- **dry_run** 告诉你会发生什么，一个字节都不动
- **apply** 真的做，每步进 journal
- **verify** 事后回现场再数一遍 —— **verify 和 apply 不一致时 verify 赢**

每个 action 还要声明 `reversible`；不可逆的 action 需要额外一个显式开关才准做。

已登记的 4 个原语：`file.write` / `service.set` / `sysctl.set` / `self.test`

**写权限用白名单不用黑名单**（黑名单是"我能想出所有危险"，白名单是"我知道哪里安全"）：
```
可写: /etc/autonomic/  /etc/sysctl.d/  /etc/systemd/system/  /run/autonomic/
拒绝: /etc/shadow  /etc/passwd  /etc/sudoers  /etc/ssh/  （保险丝，冗余一层）
```

**闭环的关键（这是整套设计最值钱的一句）：**
apply 成功 → 给 agentd 发 SIGUSR1 → action_seq +1 → 投影更新 `/run/autonomic/world`。
**于是"世界版本号"是真实变更的账本，不是装饰** ——
绕过通道的改动不计数，这个差异本身就是漂移检测的信号。

**关于放行 root 的推理**（值得记住这个思路）：拒绝 root 没有安全收益（root 直接
kill 这个进程就行），但放行有好处 —— 管理员手动操作也会走通道留下审计记录和
版本号，而不是消失在一次 shell 里。**真正要拒的是第三者**（被攻破的服务、随机进程）。

## 本轮新踩的坑

1. **dh_install 装单个模板文件会变成同名目录**
   `debian/x.conf usr/share/autonomic` → 实测装出 `usr/share/autonomic/x.conf/x.conf`，
   postinst 里 `cp` 报 "omitting directory" → dpkg configure 失败 → 整轮构建白跑。
   **解法：不要这个中间环节，postinst 里直接 heredoc 写默认值。** 少一个环节少一个失败点。
2. **git-bash → wsl 内联命令里的 `$` 被吃掉**（本轮踩了两次）
   - `sh -c 'R=/x\ndu -sh $R/...'` → `$R` 变空，**静默地**去量了宿主系统的 /usr/lib
     （症状：结果看起来合理但路径不对 —— du 输出绝对路径而不是你拼的那个）
   - `... | awk "{print \$6}"` → awk 参数变空，报 syntax error
   **规律：凡涉及 `$`，一律写成 .sh 脚本文件，用
   `wsl -d Ubuntu -u root -- bash -c 'bash /mnt/d/.../x.sh'` 执行。**
   裸 `/mnt/` 路径参数还会被 MSYS 转成 `C:/Program Files/Git/mnt/...`，同样要套进引号。
3. **decorator 的 positional-after-keyword**
   `@register("file.write", reversible=True, (...))` → SyntaxError。
   改成 keyword-only 签名 `register(name, schema, *, reversible)`，读起来也更好：
   调用处看到 `reversible=False` 应该停顿一下，那是"这一步回头不了"的意思。

# M7 ✅ 把思维接上手脚（commit 8850202）

## 缺口

M4/M5/M6 之后通道已经在了、能思考也在了，但中间是空的：
**没有任何东西把模型的话翻译成通道能接受的动作。** M7 补的就是这段神经。

```
一句话 -> 模型(提议) -> 校验 -> 预演 -> 人点头 -> 通道(裁决) -> 系统
```

## 一句话纪律：模型提议，通道裁决

模型能做的只有「提议一串动作」。它**碰不到执行入口**（dispatch 在 actd 里），
也**决定不了 phase**（dry_run/apply/verify 由 autonomicctl 选，不是它的参数）。
理由：一个被猜错意图的计划和一个恶意的计划，**在后果上没有区别**，所以走同一道闸门。

## 三道闸门（每一条都是踩过坑的）

1. **结构校验**（`extract_json`）—— 必须是 JSON。模型爱裹 ```json，也爱加客套，
   所以不能直接 json.loads，要"从第一个 `{` 做括号配平"。
   **配平必须跳过字符串内部的括号**，否则 `content = "{ }"` 就能把对象提前截断。
   截断 → 判失败，**绝不猜它的意思**。
2. **语义校验**（`validate`）—— action 必须在**真实清单**里；
   参数必须在 schema（未知参数直接拒，那是拼错或想喂不在清单里的东西）；
   路径必须在可写前缀；**每步必须有 reason**。
   **清单从 actd 实时取，绝不在代码里抄一份** —— 抄的那份从加第一个新原语那天
   就开始说谎，而模型会照着谎话规划一个不存在的 API。
   **整份通过或整份退回**：errors 非空时 steps 必为空，"部分合格"不存在。
3. **全计划预演** —— 所有步骤先跑完 dry_run，全部通过后才允许任何一步 apply。
   **顺序是硬要求**：第 1 步成功、第 3 步被拒这种半成品结果比整个拒绝糟糕得多 ——
   它留下一个既不是目的地也不是出发点的世界。

## 顺手补的真漏洞：reversible=True 之前只是声明

每次 file.write 都存备份，但**没有任何机制把备份放回原位** ——
等于给你降落伞，不给你拉环。补的：

- **备份名带微秒**：原来只到秒，同一秒内对同一文件连写两次会**静默覆盖上一版的
  备份**，也就是把"上一版"弄丢。回滚从来都是为了回到上一个状态。
- **sidecar（`<备份>.json`）记下它原本属于哪里**：名字里 `/` 被编码成 `_`，
  而 Linux 路径本身允许 `_`，所以 `etc_autonomic_my_conf` 到底指哪条路径谁也分不清。
  **猜一个文件从哪来，正是"回滚"变成"覆盖"的方式。没有 sidecar 就拒绝还原。**
- 新原语 **`file.restore`**：两端都卡死（源必须在 BACKUP_DIR 里、目标必须在可写前缀）。
  只卡一头的话，攻击者可以把"备份"指向任意文件再让它还原到别处。
- **还原本身也先备份现状**：回滚不是单行道，回滚错了还得能再回滚。
- `autonomicctl backups` 列出改过的每个文件 + 打印还原命令。

## 测试当场抓出的两个真 bug

1. **`os.path.normpath` 在 Windows 上把 `/etc/a` 变成 `\etc\a`** →
   所有合法路径都被判成"不是绝对路径"。**这些路径描述的是目标 Linux 文件系统的
   语义，跟代码此刻跑在哪个系统上无关** —— 改用 `posixpath`（autonomicplan.py
   和 autonomicact.py 都改了）。这个 bug 只在非 Linux 上跑测试才暴露，
   正好说明为什么测试要能到处跑。
2. **mock 只认不带 `/v1` 的路径**，而 setup 提示按通行写法给的是带 `/v1` 的地址。
   两边都对，改为两种都接（`_norm()` 剥可选前缀）。

## 刻意不做（下次别忘了）

- **不给 shell 逃生口**：不做"内置动作不够就用 shell 兜底"。缺能力就承认缺、加原语；
  一旦开这个口子，三道闸门**全部退化成装饰**。
- **不让模型决定 phase**：apply 是我们调用的，不是它请求的。
- **不做多轮自主循环**：一次 ask = 一个计划 = 一次人工点头。自主循环要先回答
  "没有人点头时怎么判断这件事该不该做"，这问题现在没有答案。

现在 5 个原语（file.write / file.restore / service.set / sysctl.set / self.test）。

# 装机验收暴露的三个真问题（比 M7 本身更重要）

第一次真正跑完整装机闭环（ISO→装机→硬盘启动→验收），抓到三个问题。
**其中第二个意味着我此前所有的"验收通过"都是假的。**

## 坑 1：CRLF 让每个入口在装机后都起不来（已在 d332c7a 修）

```
/usr/bin/autonomicctl: cannot execute: required file not found
```

文件在、权限 755、可执行位有，就是起不来。
根因：源码在 Windows 侧被**文本模式写回**成 CRLF，shebang 变成
`#!/usr/bin/python3\r`，内核拿这个带回车的字符串去找解释器，自然找不到。

- **"required file not found" 里的 required file 不是脚本本身，是解释器。**
  这句话的误导性正是它能藏这么久的原因。
- 两个守护进程同样中招，systemd 里表现成永远 `activating (auto-restart)`,
  看着像崩溃循环，其实**从没起来过**。
- **它完全不影响构建**，只在装机之后的硬盘系统上炸。

三层修法：① 源码转回 LF；② `.gitattributes` 早写了 `eol=lf` 但**只影响之后的
检出、不重写已入库内容** → 补 `git add --renormalize`；③ build.sh 加构建期
硬检查：打包目录里凡有 CR 就让构建失败。
另加 `scripts/check-deb-lf.sh`：解包 deb 逐个验行尾，**最后真的执行一遍**
——与其推理 shebang 对不对，不如让内核自己回答。

## 坑 2（最严重）：构建链漏了签名仓库这一步 → ISO 里是两天前的代码

**build-rootfs.sh 装 autonomic-agent 不是从 `dist/*.deb`，而是从签名的 apt
仓库 `repo/out`。**

我在 `build.sh` 之后直接跑 `build-rootfs.sh`，没重建仓库 ——
于是 rootfs 里装进去的是 **M3 时代**那个包，
`autonomicctl ask`、`file.restore`、M4–M7 的全部工作**都没进镜像**。

这个失败模式极难发现，因为它什么都不报：
构建绿灯 / ISO 体积正常 / 能开机 / 能装机 / 验收脚本大部分步骤都过。

发现方式：注意到 rootfs 里 `autonomicctl` 是 29649 字节，
而源码是 30441 —— 差了 792 字节（正是 CRLF 转 LF 少掉的部分之外的东西）。

**正确顺序（四步，中间那步不能省）：**

```
build.sh  ->  repo/make-repo.sh  ->  build-rootfs.sh  ->  make-iso.sh
```

已写进 `scripts/rebuild-iso.sh`，把四步串成一条链，不给人漏掉中间那步的机会。

⚠️ **教训：跨平台项目里"能构建"和"能在目标机上跑"是两件事。
而且"构建成功"绝不能当作"内容是新的"的证据 —— 要么查产物内容，
要么把顺序固化成脚本。**

## 坑 3：验收脚本自己在测一个空操作（还测得很满意）

原 8d 步：先 `printf > 文件`，再 `file.write` 覆盖它。
但**备份是在写完之后取的**，于是 `sha256_before == sha256_target`，
`file.restore` 正确地判定"已经就是备份里的样子，无需还原"，
输出"完成" —— 测试看到"完成"就以为过了，实际什么都没验。

改成：先落已知原稿 → 记 sha → 改 → 还原 → **逐字节比对原稿**，
并显式断言备份名里不许出现字面的 `%f`。

## 坑 4：`strftime("%f")` 是个假的微秒

`time.strftime` **没有 %f 指令**（那是 datetime 的），它把 `%f` 原样吐出来
→ 备份名里出现字面的 `%f` → 同一秒内两次备份还是撞在一起，
**把"上一版"弄丢，而回滚的全部意义就是回到上一版**。

改用 `time.time()` 自己算微秒。已真验：连写两次，两次备份相隔 578μs、
名字不同、内容各是各的（v1 / v2）。
`scripts/test-backup-naming.py` 把这个主张变成可执行断言（13 项全过），
顺带验 sidecar 能还回原位置、没有 sidecar 时必须拒绝而不是猜。

8a 合法计划 → 2 步全预演过 → 落地 → 逐步 verify → 世界版本号 +2 → 留痕 plan-<ts>.json
8b 越界     → 计划被拒绝，一步都没有执行：参数 path 在系统保护名单上：/etc/ssh/sshd_config
8c 不合格   → 计划被拒绝，一步都没有执行：未登记的 action 'rm_rf'（可用：file.restore,
              file.write, self.test, service.set, sysctl.set）
8e 留痕     → plan-...190826.json + plan-...190827.json（被拒的那次也留了）
```

**8b/8c 的措辞值得记：输出是"计划被拒绝，一步都没有执行"而不是"第 X 步失败"** ——
这就是"整份通过或整份退回"在用户可见层的落点。

## 环境坑（又踩）

- **git-bash 的 `/tmp` 与 WSL 的 `/tmp` 不是同一个地方** ——
  在 git-bash 写 `/tmp/x.sh` 再让 WSL `bash /tmp/x.sh` → `No such file`。
  跨系统传递一律写进**项目内**路径。
- **`python -c` 内联改文件不可靠**：本轮用它转 LF 时，两个文件被写成 0 字节
  （`restore-probe.py` / `run-probe.sh`，所幸都是临时文件）。
  改文件一律用 Write/Edit 工具，别用内联 python。
- **WSL 转发 stdout 偶尔整段丢失**（脚本明明跑完、rc=0，输出为空）→
  让脚本自己 `tee`/重定向到项目内的日志文件，再读文件。
- **VBoxManage 路径是 git-bash 风格（`/c/Program Files/...`）**，
  所以 `install-test.sh` 只能在 git-bash 里跑，**不能在 WSL 里跑**。
- **WSL 里跑项目脚本要 `MSYS_NO_PATHCONV=1`**：否则 `/mnt/d/...` 被 MSYS 转成
  `C:/Program Files/Git/mnt/d/...`，报 "No such file or directory"。

# M8 ✅ 加原语，不加权力

通道从 5 个原语扩到 9 个，**一次都没放宽约束**。

## 新增

- `pkg.install` / `pkg.remove` / `pkg.list` —— apt
- `user.add` —— 第一个不可逆原语

## 两条红线，各写在代码里

**`pkg.install` 是通道上第一个执行"别人写的代码"的动作**（Debian postinst
以 root 跑）。所以包名硬校验：Debian 字符集、不许以 `-` 开头（否则
`--allow-unauthenticated` 会被 apt 当成自己的选项吃下去）、不许带 `=`
指定版本（能挑版本就能挑到有洞的版本）、一次最多 5 个包。
dry_run 用 `apt-get -s` 让 apt 自己算依赖树；verify 只问 `dpkg-query` 的
Status，不信 apt 说了什么。

**`user.add` 是第一个不可逆原语**，也是第一次让 `--force-irreversible`
真正派上用场。它 revertible=False 的理由：删用户不会把文件/服务/写进别处
配置的 UID 一起带走。**那个额外的停顿就是安全机制本身。**
测试里专门钉了断言 `user.add.reversible is False` —— 声明错了机制就废了，
而声明错是不会报错的。

## 取舍：pkg.install 为什么反倒标"可逆"

`pkg.remove` 能拿掉包，但 /etc 配置残留不会消失（那要 purge）。
仍标 True，因为通道承诺的是"有回头路"不是"世界完全复原"。
**把什么都标不可逆的系统，和什么都不标的一样没用 —— 没人再会为那个标记停顿。**
诚实的做法是把边界写在明处。这条也写进 changelog 了。

## 刻意不做

`apt upgrade` / `dist-upgrade`（跨版本太多，预演给不出有意义的答案）·
`user.del` / `user.modify`（删用户前检查没想清楚之前宁缺毋滥）·
版本指定 · 第三方源 · 任何"自定义参数"逃生口。

`scripts/test-primitives.py` 39 项，全纯函数（不装包、不建用户、不碰系统）。
在 WSL 真 Linux 上跑：75 ok / 0 FAIL（含 test-plan 21 + backup-naming 13）。

# 验收脚本自身的两个真坑（这轮抓的）

## 坑 A（阴）：`pkill -f mock-llm.py` 在 SSH 单命令行里会杀掉自己

第 8 步的 mock 一直起不来，我此前归因于"setsid 不够"。**真正原因不是那个。**

```
pkill -f mock-llm.py
```

写在这条 SSH 命令里时，**pkill 匹配到承载这条命令的 shell 自己** ——
它的命令行里就含 "mock-llm.py" 这几个字。于是命令自杀，
**SSH 返回 255，整段 stdout 凭空消失**。看起来像网络问题。

证据：把 pattern 改成 `m""ock-llm.py`（拼字符串绕开自匹配）后，同一条命令 rc=0。

正解：**`systemd-run --unit=aosmock --collect python3 .../mock-llm.py`**。
交给 systemd 托管 → 完全脱离 SSH 会话、不继承任何 fd；停它用
`systemctl stop aosmock` 而不是 pkill，一个改动拆掉两个问题。
实测 `is-active=active` + curl 拿到模型列表。

⚠️ 教训：**"命令输出整段消失 + rc=255" 不要先怀疑网络，先想想
这条命令里有没有东西匹配到了它自己。**

## 坑 B：check-deb-lf.sh 把版本号写死

`autonomic-agent_0.3.0-1_all.deb` 硬编码在脚本里。构建升到 0.4.0 后，
它去解一个不存在的包 → 所有文件报 `<缺失>` → 看起来像"deb 坏了"，
其实是检查脚本指向了错的东西。改为 `ls -t dist/*.deb | head -1`。

# M8 首次验收（新 ISO）：9 个原语都出来了，但抓出三个真 bug

**这次改了做法：不光看"验收通过"，还逐行读输出。** 于是抓到三个。

`autonomicctl actions` 已经正确列出 9 个原语，`user.add` 标着"不可逆"，
第 7 步的越界/注入守卫三条全按预期被拒（`Bad;Name`、`nginx; rm -rf /`）。

## bug 1（最严重）：不可逆的动作被静默报成"可逆"

```
Action: user.add
  OK   dry_run  将新建用户 aos-acceptance-probe（shell=/bin/bash）
  可逆  : 是        ← 错。登记的是 reversible=False
```

根因：`dispatch` 里用 `result.setdefault("reversible", fn.reversible)`，
而 **`ok()` 的默认参数恰好就是 `reversible=True`**。两者一叠加，
**任何**返回 `ok(...)` 却没显式传 reversible 的 handler，dry_run 都会被
报成"可逆"。

后果不是显示错误：`cmd_act` 里 `if not preview.get("reversible")` 那道
两级授权拦截**根本不触发**，一个不可逆的动作可以被一句 `--yes` 带过。
而 `autonomicctl actions` 显示是对的 —— **只看那一行永远发现不了。**

而且早返回的路径（未知 action / 参数不合格 / handler 抛异常）都走
`fail()`，那个函数也硬写着 `reversible: True`。

修法：可逆性**只能声明一次**（`@register`），`dispatch` 里写一个 `seal()`
把所有返回路径统一收口强制覆盖；连 action 都没认出来时标 `None`，
不假装它可逆。测试钉了两条：`user.add` 的 dry_run 必须报 False、
handler 自己撒谎（在返回值里写 `reversible=True`）也必须被纠正回来。

**教训：一个性质若在两处被声明，副本迟早撒谎。**

## bug 2：`user.add` 的"已存在就早返回"把 verify 变成空操作

那句 `if existing is not None: return ok(...)` 写在三个阶段前面，
于是 verify 一看"用户存在"就报成功 —— **从没检查建出来的用户 shell 对不对**。
verify 的全部价值是"去现场把 apply 承诺的每一项再数一遍"，提前返回
等于自己把这一步废掉了。改成只在 dry_run 生效。
顺带 apply 阶段也处理"已存在"：不再 useradd（它会失败），
且 `changed=False` —— 世界版本号要为真实变更 +1，不该虚增。

## bug 3（可测性）：`pwd` 只在 POSIX 有

`import pwd` 写在函数内部，于是 **user.add 在 Windows 上永远只会撞
ModuleNotFoundError**，dry_run 的正常路径一次都测不到。

抽出 `_passwd_lookup()`：三个阶段共用同一个真相来源（而不是各写一遍
try/import/except —— 三份副本迟早漂移），且**能在测试里被替换**。
测试覆盖因此从"只能测异常分支"变成真的测正常路径。

`test-primitives.py` 39 → 48 项；Linux 全套 83 项全绿（plan 21 +
primitives 48 + backup 13 + 1）。

# M9 感知层：让 agent 第一次看见系统

用户指令：「继续。同时别忘了也要让Agent能真正操作系统」。

## 诊断：agentd 是"心跳 + 版本号账本"，它看不见系统

跑在 `ProtectSystem=strict` + `ProtectProc=invisible` + `ProtectKernelTunables=yes`
下面，物理上读不到 `/proc`、`/sys` 和别的进程。**这是沙箱在正常工作。**

两条路：放宽沙箱（**加权力**）· 让有权限的一方替它读（**加能力**）。
选了后者 —— 于是**感知也是一个原语**。

## 加了两个只读原语（通道 9 → 11 个）

- `sys.read(metric)` —— 9 个白名单指标：`os.release` / `kernel` / `hostname` /
  `uptime` / `loadavg` / `meminfo` / `cpuinfo_count` / `disk_usage` / `timezone`
- `service.status(unit)` —— active / enabled / substate

三条硬约束：
1. **看也要留痕** —— 走 act.sock → actd → 审计，和写文件同一条路
2. **只读一律 `changed=False`，不推进 `action_seq`** —— 否则"从我上次看到现在
   它变了没有"这个问题的答案永远是"变了"，账本退化成访问计数器
3. **指标名是闭集，不是路径** —— `sys.read` 若收路径就是任意文件读取漏洞
   （`/etc/shadow` 也是文件）

## `autonomicctl sense` —— 一次拿全

逐项问通道 → 投影到 `/run/autonomic/sense`（0444，附当时的世界版本号）。

两个设计决定：
- **清单写死在调用侧**，不是问 actd "有什么读什么" —— 后者是漂浮的目标，
  加个原语快照就不可比了；对不上就是链路有缺口，应该被看见
- **取不到的照样写进去，标 `unavailable` + 原因** —— "少了几行"看起来像
  一切正常，写着取不到的才在说实话

返回码：全读到 0 / 部分读到 **0**（容器常态，不该报成故障）/ 全无 1。

## 又一次撞上 M8 bug 3 的同一个坑

`os.statvfs` 在 Windows 上不存在 → `AttributeError`（不是"读失败"）。
**"这台机器的 Python 没有这个调用"和"statvfs 失败了"是两件事** ——
混成一句会让人去查权限，其实该查的是平台。

修法同 bug 3：抽成**可替换的小函数**。顺带修了三处同类毛病：
- `autonomicctl` 导入期就 `import grp/pwd` → 改成容忍缺失
- `_act_call` 直接用 `socket.AF_UNIX` → 给回退，返回一句可读的话
- sense 投影失败不该让**已经读到的信息**消失
