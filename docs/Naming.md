# Naming · 对外命名候选与理由

> **最终定名由桂鱼裁决。本文档只负责把候选与理由摊开，不做决定。**
>
> 定名前：**不把品牌名固化到包名 / 用户名以外的地方**。
> 因此当前包名 `autonomic-agent`、系统用户 `autonomic` 只是占位，改名成本低。

---

## 0. 诉求（桂鱼原话）

- **绝大部分人能看懂**，不只是专业的人
- **不要缩写**
- 名字要承载卖点

## 1. 判断规则（本轮最重要的一条）

定位从"**社会角色**"（受托的雇员）变为"**生物器官**"（内生的部分）→
命名隐喻应从**社会**转向**生物**。

> **名字听起来要像"器官 / 内在能力"，而不是"装上去的东西"。**
> 凡像外挂（Assistant / Copilot / Agent / 插件式词）→ 排除。

---

## 2. 候选表（2026-10-09 复议）

| 顺位 | 名字 | 语义 | 代价 |
|---|---|---|---|
| ⭐ **主推** | **Autonomic OS**（自主神经系统） | **结构逐点对应**：① 是身体的一部分（原生，不是外挂）② 不受意识控制常驻运行（平时隐身观察）③ 危急时接管全身（必要时最高权限介入）④ 有分层（交感/副交感/肠神经 ↔ T0–T3） | 中文"自主"有信创（自主可控）混淆风险；词偏学术 |
| 并列（中文最强） | **机魂 / Anima OS** | 中文极简要、秒懂、够酷；"机器本身有魂" = 原生智能 | 英文 Anima 中等撞名；不直接说"接管" |
| 保底 | **Steward OS**（管家） | 上轮结论；最容易向任何人解释 | 语气偏服务，弱化"底层接管"的锐度 |

**当前倾向：`Autonomic OS`** —— 它一次说出了"**原生 + 常驻 + 接管**"三件事，
另外两个各只说了一件。

---

## 3. 出局名单与理由（别再捡回来）

| 名字 | 出局理由 |
|---|---|
| **Ghost / Shadow / Daemon** | ① 撞名严重（Ghost OS 撞商业站 + 1.7k★ 仓库 + 两个自称 Agent OS 的项目）。② 更根本：**语义递刀** —— 给"以最高权限介入你的机器"加了一层"不请自来、不可见、不受控"的恐惧叙事，恰是这类系统最需要防守的质疑。护栏（带外通道、拒绝权、审计轨迹）是卖点，名字不该反向削弱它 |
| **Ainux / Agentix / Ghostix** | **语义自相矛盾**：`-nix` / `-ux` 在技术语境里不是"这是个 OS"，而是"**这是个 Unix 系内核或发行版**"。用它去命名一个第一原则是"不魔改 Ubuntu"的系统 → 第一个问题就会变成"你的 kernel fork 在哪？"，答案是没有。**开场即失分，失的还是最想强调的卖点** |
| **AOS** | ① **缩写**（违反硬诉求）。② **是类别词不是名字**（等于给车起名"汽车"）。③ 撞两篇同名 arXiv。→ 降为架构类别词，永不作产品名 |
| **Guardian** | 撞名最多最泛，且**只覆盖一半语义** —— "守护"弱化了"必要时**接管**"，而接管才是这个项目的胆子 |
| **Conductor** | 语义很好（站全体之上指挥但不演奏 = 控制平面在数据平面之上），但要转一下脑子；作备选保留 |

一句话差别：**Guardian 讲"我在看着你"，Steward / Conductor 讲"我可以替你接管"**。

## 5. 落地约定（定名后照此执行）

- **目录 / 仓库名**：`<名字小写>-os`（**别再用 `AOS` 当目录名** —— 观众看到的第一个字就是它）
- **二进制 / 包名**：待定（当前 `autonomic-agent`）
- **系统用户名**：待定（当前 `autonomic`）
- **README 首行**：`<Name> — an agent-native layer for Debian/Ubuntu.`
- **学术定位段**（仅此一处用类别词）：`...an Agent OS (AOS) in the sense of arXiv 2606.01508, but implemented natively rather than out-of-band.`
