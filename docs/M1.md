> 状态：**施工中**（2026-10-09 开工）
> 上游依据：`docs/CHARTER.md`

## 0. M1 只做一件事

**让 Agent 在系统里有一个身份，而不是一个进程。**

不做完整发行版，不做 ISO，不做自主诊断，不搬旧台架。

---

## 1. 交付物

| # | 交付物 | 位置 |
|---|---|---|
| 1 | **自己的 apt 仓库**（GPG 签名 + 静态 HTTPS 托管） | `repo/` |
| 2 | **一个真实的 `.deb`**（`autonomic-agent`，debhelper 正常构建） | `packaging/autonomic-agent` |
| 3 | 装上后 Agent 具备：独立系统用户 / systemd unit（hardening 开着）/ cgroup 限额 / 自己的日志命名空间 / 只读世界版本标记 | 包内 |
| 4 | **可复现构建**：容器化脚本 + CI，别人能重跑出同一个包 | `build/`、` .github/workflows/` |
| 5 | `docs/CHARTER.md` + `docs/Naming.md` | `docs/` |

### 交付物 3 的五个可验证点

| 点 | 实现手段 | 为什么它是"身份"而不是"进程" |
|---|---|---|
| **独立系统用户** | `adduser --system --group autonomic`（专有 UID/GID） | 系统把 Agent 当**一个主体**来记账，不是 root 下的一个子进程 |
| **systemd unit** | `autonomic-agent.service`，hardening 全开 | 系统的**服务管理器**认识它、能启停、能设依赖 |
| **cgroup 资源限额** | `MemoryMax` / `CPUQuota` / `TasksMax` | 它**占用资源是受控的**，区别于任何失控脚本 |
| **自己的日志命名空间** | `LogNamespace=autonomic` | 它有**自己的审计流**，不与系统日志混在一起 |
| **只读世界版本标记** | `/run/autonomic/world` = `(snapshot_id, action_seq)`，0444 | 世界版本号是**系统外的单调计数器**；系统内只有只读投影 → 可检测绕过通道的漂移 |

## 2. 验收标准（逐条可验证）

- [ ] 在**原厂 Ubuntu 虚拟机**里：加一行 `sources.list` → `apt update` → `apt install autonomic-agent` → `systemctl status` **绿**
- [ ] `getent passwd autonomic` 有条目；`ps -u autonomic` 能看到 Agent 跑在**它自己的 UID** 上
- [ ] `systemd-cgls` / `systemctl show` 能看到**限额生效**（memory.max / cpu.max）
- [ ] `journalctl --namespace=autonomic` 能查到它的日志，且**系统日志里查不到**
- [ ] `/run/autonomic/world` 存在、**只读**（0444），内容随 action_seq 单调变化
- [ ] `apt remove --purge` 后**清洁卸载**（无残留用户 / unit / 文件）
- [ ] 构建**在干净环境里可重跑**，产出相同包名与版本
- [ ] 一条演示脚本：一条命令展示"**它是系统的一个角色，不是一堆脚本**"

---

## 3. 明确不做（这一版）

- ❌ 不重写内核 / init / C 库 / 包管理格式
- ❌ **不做完整 ISO**（顺序是 **仓库 → 包 → ISO**；先做 ISO 的人最后都卡在打包上）
- ❌ 不做自主根因分析（已有证据说明不可靠）
- ❌ 不搬 VirtualBox 台架
- ❌ **不迁移、不重构旧 AOS 代码** —— 先做出能装的东西，再回头决定搬什么
- ❌ 不做多 Agent 编排

## 4. 环境（本机实测，2026-10-09）

| 角色 | 是什么 | 备注 |
|---|---|---|
| **构建机** | WSL `Ubuntu` 24.04.3 | 有 `dpkg-dev` / `gpg` / `python3`；需补 `debhelper` `apt-utils` |
| **验收靶机** | VirtualBox `aos-node`（**原厂 Ubuntu 24.04.5**，systemd 255） | SSH：`ssh -i D:\Code\AOS\vm\keys\id_ed25519 -p 2222 aos@127.0.0.1` |
| **容器运行时** | ❌ 不可用（docker-desktop 已注销，daemon 起不来） | → 可复现构建靠 **Dockerfile（CI 资产）+ GitHub Actions runner** |

> systemd 255 支持 `LogNamespace` —— 这是"自己的日志命名空间"能用 systemd 原生机制实现、
> 而不是自己造一个日志文件的前提。
