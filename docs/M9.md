# M9 · 感知也要走通道

> 状态：**✅ 已交付（2026-10-11）**
> 上游：M5 给了一条只能走入口的通道，M8 证明这条通道能长大
> M9 让 agent 第一次**看见**这台机器 —— 而且看一眼也要留痕

---

## 0. M9 只做一件事

**让 agent 能"看见"系统，而且"看"和"改"走同一条门。**

到 M8 结束为止，`autonomic-agentd` 是一个**心跳 + 版本号账本**：它知道自己
的 uid、自己的 cgroup 限额、世界版本号推到第几了。但它对**这台机器本身**一无所知
—— 它不知道跑的是什么内核、还剩多少内存、根分区快满了没有。

问题不是"没想到去读"，是**它读不到**：

```
ProtectSystem=strict
ProtectProc=invisible
ProtectKernelTunables=yes
```

一个跑在 `ProtectProc=invisible` 下的进程，物理上看不见别的进程，也看不见
大部分 `/proc` 和 `/sys`。**这是沙箱在正常工作**，不是故障。

---

## 1. 摆在面前的两条路

想让 agent 看见系统，只有两条路：

| | 做法 | 性质 |
|---|---|---|
| **甲** | 放宽 agentd 的沙箱，让它自己读 `/proc` | **加权力** |
| **乙** | 让有权限的一方（actd，root）替它读，结果交回来 | **加能力** |

甲看起来更省事，但它做的事是：把一个**已经**被关起来的进程重新打开一扇窗，
而窗户一旦开了，就没有"只看这些"这回事 —— `ProtectProc=invisible` 是**一刀切**
的，要放宽就只能整个放宽。为了让 agent 看见内存用量，代价是让它重新看见系统里
所有进程。这笔账不划算。

M9 走的是乙。这一条决定把后面所有设计都定了下来：

> **感知是一个原语。它和写文件、装软件包走同一条通道、进同一份审计。**

---

## 2. 三条硬约束

### 2.1 看也要留痕

"agent 什么时候看了什么"和"agent 改了什么"是同一件事的两面。

一个半夜在遍历 `/proc` 的进程，是值得有人问一句"它在找什么"的。如果感知
绕开通道，这次"看"就不会出现在账本上 —— 那么审计记录的就不再是"agent 做了
什么"，而只是"agent 做过的、恰好被记下来的那些事"。

所以 `sys.read` / `service.status` 走的是和 `file.write` 完全相同的路径：
`autonomicctl → act.sock → actd → 审计落盘`。

### 2.2 只读原语不推进世界版本号

世界版本号（`action_seq`）的**全部意义**是回答一个问题：

> "从我上次看这台机器到现在，它变了没有？"

如果一次读取也把 `action_seq` 推高，这个问题的答案就永远是"变了" ——
账本从一个变更台账退化成一个访问计数器。

所以只读原语一律 `changed=False`，接在后面的 `SIGUSR1` 就不会发出去，
世界版本号一动不动。`sense` 里刻意**没有**任何 apply 阶段的东西，
测试里有一条专门盯着这件事：

```python
check("sense 全程没有调用任何 apply 阶段的东西（只有 dry_run）", ...)
```

### 2.3 指标名是闭集，不是路径

这是 M9 唯一一处真正危险的地方。

`sys.read` 如果接受一个**路径**，它就是一个任意文件读取漏洞：
`/etc/shadow` 也是文件。而一个"能读任意文件的 AI 通道"，比一个"能写指定
文件的通道"更好用、也更难审计 —— 写是被 allowlist 关着的，读却会悄悄变成
"把机器上的秘密全部打包发走"。

所以 `sys.read` 收的是**指标名**，名字对应一段**我们写死的读法**：

```python
_READ_PROBES = {
    "os.release": ("file", "/etc/os-release"),
    "kernel":     ("file", "/proc/sys/kernel/osrelease"),
    ...
    "disk_usage": ("disk_usage", None),   # 一段小逻辑，不是一个路径
}
```

调用者给不出路径。要加新指标就改这张表 —— 改表要过 code review、要写测试，
**不由提示词里的一句话决定**。

测试里钉住了这一点：

```
ok   把路径当指标名传 -> 拒绝
ok   带路径穿越的指标名 -> 拒绝
ok   指标名大小写敏感（不做猜测性归一化）
```

## 3. 这一版感知能看见什么

### 3.1 `sys.read(metric)` —— 9 个白名单指标

| 指标 | 读法 |
|---|---|
| `os.release` | `/etc/os-release`，压成一行 `PRETTY_NAME` |
| `kernel` | `/proc/sys/kernel/osrelease` |
| `hostname` | `/proc/sys/kernel/hostname` |
| `uptime` | `/proc/uptime` |
| `loadavg` | `/proc/loadavg` |
| `meminfo` | `/proc/meminfo` |
| `cpuinfo_count` | `os.sched_getaffinity(0)`，回退到数 `/proc/cpuinfo` |
| `disk_usage` | `os.statvfs("/")`，算出 total / used / free / used_pct |
| `timezone` | `/etc/timezone` |

### 3.2 `service.status(unit)` —— 一个服务现在怎么样

单独一个原语，而不是让 `sys.read` 去读 `systemctl`。理由和"解析命令行输出
应该只有一份实现"一样：`systemctl is-active` / `is-enabled` / `SubState`
的解析只写一次，别处都调它。

unit 名要挡住参数注入（`--help`、`-x`、`a/b`、`../../etc/passwd`），
因为 `systemctl` 会把 `-` 开头的东西当自己的参数。

## 4. `autonomicctl sense` —— 一次拿全

单独跑 `sys.read` 九次能拿到九个值，但**拿到的不是一份快照** ——
九次调用之间世界可能已经变了。

`sense` 做的是：

1. 按 `_SENSE_METRICS` 里**写死的清单**逐项问通道（不是问 actd "有什么就读什么"）；
2. 顺带问 `_SENSE_UNITS` 里那几个服务的状态；
3. 把结果投影成一份只读文本 `/run/autonomic/sense`（`0444`）；
4. 顺带把当时的世界版本号写进投影首部。

### 4.1 为什么清单要写死在这边

问 actd "有什么就读什么"是一个**漂浮的目标**：actd 加一个新原语，
agentd 的感知内容就跟着变，于是前后的快照**不可比**。

清单写死在 `autonomicctl` 这边，两边对不上就是**这条链路有缺口** ——
那应该被看见，不该被吞掉。

### 4.2 取不到的，照样写进去

一份"少了几行"的快照看起来像一切正常。一份明确写着 `unavailable`
并附上原因的，才是在说实话：

```
hostname=unavailable (读不到指标 hostname（/proc/sys/kernel/hostname）——
          可能这台机器上没有这个文件，也可能被沙箱挡住)
```

⚠️ 注意这里的措辞：**"这台机器上没有这个文件"和"被沙箱挡住"是两件事。**
硬要二选一，会给出一个确定的错答案。并列两种情况，让操作者自己核。

### 4.3 返回码的含义

- 全部读到 → `0`
- 读到一部分 → `0`（**容器里的常态，不该报成故障**）
- 一项都读不到 → `1`

"部分读到"恰恰是操作者最需要知道的事实。用一个非零返回码盖过去，
会让人以为整个感知坏了。

## 5. 刻意不做的四件事

| 不做 | 为什么 |
|---|---|
| 放宽 agentd 的沙箱 | 那是**加权力**。为了看内存用量而重新看见所有进程，账不划算 |
| 让 `sys.read` 接受路径 | 那是任意文件读取漏洞。`/etc/shadow` 也是文件 |
| 让 `sense` 自动定期跑 | "agent 自己在看什么"和"人让它看什么"是两种东西。定期跑要做成**显式的订阅**，不是偷偷跑 |
| 把感知结果喂回模型的上下文 | 这一版只做到"能看见、看得见、留了痕"。**怎么用**是 M10 的事，得先有可信的感知，再谈怎么思考 |

## 6. 修掉的一个平台坑（和 M8 的 bug 3 同一条教训）

M8 的 bug 3 是：`pwd` 只在 POSIX 上有，于是 `user.add` 的正常路径在非 Linux
上**永远测不到**，只剩错误分支可测。改法是抽出 `_passwd_lookup()`，
让它可被测试替换。

M9 写了 `sys.read` 之后，同一个坑立刻又出现了一次：

```
disk_usage -> sys.read 在 dry_run 阶段出错：AttributeError:
              module 'os' has no attribute 'statvfs'
```

不是"statvfs 失败了"，是**这台机器的 Python 根本没有这个调用**。
两者要说清楚 —— 混成一句话会让人去查权限，其实该查的是平台。

修法和 bug 3 一样：把平台相关的调用抽成**可替换的小函数**。

```python
def _probe_disk_usage() -> str:
    statvfs = getattr(os, "statvfs", None)
    if statvfs is None:
        return "(这台机器的 Python 上没有 statvfs，指标不可得)"
    ...
```

顺带修掉同一类毛病的还有三处：

- `autonomicctl` 在**导入期**就 `import grp / pwd` —— 一个连 import 都过不去的
  工具，在非 Linux 上连 `actions` / `sense` 这些跟平台无关的命令都跑不了。
  改成容忍缺失，把"没有它"推迟到真正要用它的那一个命令里说。
- `_act_call` 直接用 `socket.AF_UNIX` —— 非 POSIX 上它不存在。同样给了回退，
  返回的是一句可读的话（"Action 通道只存在于 Linux 上"），不是一个 `AttributeError`。
- `sense` 里投影失败（比如目标是个目录）不该让**已经读到的信息**消失 ——
  屏幕上已经打过了，快照内容仍然有效。

## 7. 验收

Linux 上全套自检 **142 项全绿**：

| 套件 | 项数 |
|---|---|
| `scripts/test-plan.py` | 24 |
| `scripts/test-primitives.py` | 80 |
| `scripts/test-sense.py` | 28 |
| `scripts/test-backup-naming.py` | 9 |

`test-sense.py` 钉的不是"读到的值对不对"（每台机器都不一样），而是三件更安静的事：

```
sense 只能经由通道看 —— 每一次读都必须在审计里
  ok   每一个 sys.read 都经由 _act_call（没有绕过通道自己读）
  ok   sys.read 的 phase 一律是 dry_run（只读不该走 apply）
  ok   服务状态经由 service.status 走通道，不是自己调 systemctl
  ok   投影是 0444（写一次就不许就地改）
  ok   投影里带着世界版本号（读的时候系统处于哪个版本是快照的一部分）

取不到的指标必须显式写进快照，不能悄悄少一行
  ok   取不到的 os.release 仍出现在快照里并标注 unavailable
  ok   取不到时写清了原因（不是干巴巴一个 unavailable）
  ok   一项都读不到 -> 返回 1（部分读到不该算失败，全无才算）

只读的快照不许推进世界版本号
  ok   sense 全程没有调用任何 apply 阶段的东西（只有 dry_run）
  ok   sense 只碰 sys.read / service.status（不下发任何写入原语）

调用侧清单与 actd 白名单必须对齐 —— 对不上就是链路有缺口
  ok   _SENSE_METRICS 里的每一项 actd 都真的能读
  ok   actd 能读的没有一项被 sense 漏掉（漏了就是白加了原语）

版本号推进有两道独立闸门，感知一道都过不去
  ok   actd 的推进条件是 ok && changed && phase==apply（三条都要满足）
  ok   闸门一（actd 要 apply）与闸门二（sense 只发 dry_run）同时成立
```

最后那两条值得单独说一句。"感知不推进世界版本号"这件事有**两道独立的闸门**：
actd 只在 `ok && changed && phase==apply` 时才发 `SIGUSR1`（只读原语报
`changed=False`，所以过不去），而 `sense` 从头到尾只发 `dry_run`（也过不去）。
两道都测，才算证明了这件事 —— **只测一道，另一道坏了也没人知道。**
