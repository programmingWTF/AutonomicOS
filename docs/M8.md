# M8 · 加原语，不加权力

> 状态：**✅ 已交付（2026-10-11）**
> 上游：M5 给了通道，M7 让模型能把话说进通道
> M8 用同一套纪律把"能做的事"从 5 件扩到 9 件 —— 而且一次都没有放宽约束

---

## 0. M8 只做一件事

**证明这套设计是能长大的：加能力靠加原语，不靠加权力。**

M7 结束时通道里有 5 个原语，全都改的是"配置"一类的东西：写文件、启停服务、
调内核参数、自检。这些足够把一台机器**调**成想要的样子，但不足以把它**变成**
想要的样子 —— 装不了 nginx，开不了账户，就碰不到"这台机器还是不是 Linux"
这个问题的答案。

M8 补上第一批真正碰到底层的动作：

```
pkg.install / pkg.remove / pkg.list      软件包
user.add                                 账户
```

---

## 1. 为什么这次要特别小心

前 5 个原语都是"幂等、可逆、不执行外来代码"的。新加的这三个里：

- **`pkg.install` 是通道上第一个执行"别人写的代码"的动作。**
  apt 的 postinst 以 root 跑，装进来什么，就执行什么。这不是副作用，
  这是 Debian 软件包的正常定义。所以这条通道一旦开了装包的口子，
  它在效果上就接近"能装什么就能执行什么"。

- **`user.add` 是第一个真正不可逆的动作。**
  删掉一个用户，不会把它创建过的文件、跑过的服务、写进配置里的 UID 一起带走。
  把"删了用户"当成"回到没建过这个用户"是错的。

换句话说，M8 加的两件事，恰好各自踩在一条红线上。**这正说明为什么规矩要
写在代码里，而不是写在对面的自律里。**

---

## 2. 规矩（每条都对应一种真实攻击）

### 2.1 包名是第一个注入面

即使不经过 shell（`subprocess` 给的是 argv 列表，压根没有 shell），
包名仍然有三个可以被利用的地方：

| 输入 | 如果没有这道闸门，会发生什么 |
|---|---|
| `--allow-unauthenticated` | apt 把它当成**自己的选项**吃下去，装上未签名的包 |
| `nginx=1.14` | 指定版本 —— 能挑版本，就能挑到一个有洞的版本 |
| `a; rm -rf /` | 在没有 shell 的地方它只是"一个奇怪的包名"，但纵深防御不该赌"没有 shell"这一层不会破 |

所以 `_split_packages()` 强制：

- 匹配 Debian 包名字符集（`^[a-z0-9][a-z0-9+.\-]*$`），**必须以字母数字开头**；
- 不许含 `=`、通配符、空白、引号；
- **一次最多 5 个包** —— 爆炸半径写在代码里。

### 2.2 `--simulate` 是免费的，而且比我们自己猜依赖树可信

`dry_run` 阶段直接跑 `apt-get -s install …`。apt 会把"会装哪些、会卸哪些、
要下多少"完整算一遍，一个字节都不动。**预演的价值不在我说了什么，在系统自己说了什么。**

### 2.3 verify 不看 apt 说了什么

apply 阶段 apt 返回 0 不代表包装好了（依赖冲突、dpkg 中断都可能让它"返回成功但没配置完"）。
所以 verify 只问一个权威口径：`dpkg-query -W -f='${Status}'` 是不是 `install ok installed`。

### 2.4 不可逆必须被"声明"出来

这是 M8 最值钱的一条。`user.add` 标 `reversible=False`，于是：

```
autonomicctl act user.add name=alice --yes
  -> 拒绝：这个 action 不可逆。真要继续，请显式加 --force-irreversible。
```

**那个额外的停顿就是安全机制本身。** `--yes` 的意思是"别问我了"，
而不可逆的事需要的不是"别问我了"，是**再问一次**。

如果 `user.add` 悄悄标成 `reversible=True`，调用侧就不会有这个停顿，
于是一个本该在书面上不可逆的动作，可以被一句"继续"带过。
所以测试里专门钉了一条断言：

```python
check("user.add 声明为不可逆", act.ACTIONS["user.add"].reversible is False)
```

**声明错了，机制就废了 —— 而声明是不会报错的。**

### 2.5 pkg.install 标"可逆"是诚实但有限度的

`pkg.remove` 能把包拿掉，但 `/etc` 下的配置残留不会自动消失（那要 purge），
家目录里的数据也不会。

之所以仍然标 `reversible=True`：这条通道承诺的是**"有回头路"**，
而不是**"世界完全复原"**。把"卸了但留了配置"说成不可逆，会让真正不可逆的
那些（`user.add`）失去重量。

**诚实的做法是把边界写在明处，而不是把所有事都夸大** —— 一个什么都标"不可逆"的
系统，和什么都不标的一样没用，因为没人再会为那个标记停顿。

## 4. 验收

```
$ python3 scripts/test-primitives.py
原语清单：新加的东西必须真的登记上，且边界声明正确
  ok   user.add 声明为不可逆
  ok   pkg.install 声明为可逆（apt remove 能拿掉）
_split_packages：包名是第一个注入面，必须一个都不放过
  ok   以 - 开头的'包名'被拒（防 apt 选项注入）
  ok   非法包名 'nginx; rm -rf /' 被拒
  ok   带 = 指定版本被拒
  ok   超过 5 个包被拒（爆炸半径写死在代码里）
_USER_RE：用户名要过 POSIX 可移植字符集，且不能是纯数字
  ok   非法用户名 '-lead' 被拒
  ok   非法用户名 'user;rm' 被拒
dispatch：校验在进入函数之前就完成，非法参数不应触达真实的 apt/useradd
  ok   dispatch 挡住注入的包名
  ...
全部通过。   （39/39）
```

这些全是纯函数测试 —— 不装包、不建用户、不碰系统，1 秒跑完。因为要验的
是**"非法的东西到底能不能进门"**，而这件事跟门外有没有真 apt 无关。

### 装机验收（真机、真硬盘、真 systemd）

重建 ISO → 装机到 /dev/sda → 拔盘 → 从硬盘启动，然后在**已安装的系统上**
逐条核验。第 7 步的输出：

```
--- 通道愿意做的事，一共就这些 ---
  file.write     可逆   参数: path, content, mode?
  file.restore   可逆   参数: backup
  service.set    可逆   参数: unit, state
  sysctl.set     可逆   参数: key, value
  pkg.install    可逆   参数: packages
  pkg.remove     可逆   参数: packages
  pkg.list       可逆   参数: pattern?
  user.add       不可逆   参数: name, shell?, groups?, gecos?

--- 不可逆原语的两级授权：只给 --yes 时必须仍被拦下 ---
Action: user.add
  参数  : name=aos-acceptance-probe
  OK   dry_run  将新建用户 aos-acceptance-probe（shell=/bin/bash）
  可逆  : 否 —— 做下去就回不来
                                     ← 到这里就停了，没有 apply
--- 反过来：用户名非法时，连 dry_run 都进不去 ---
  FAIL dry_run  用户名 'Bad;Name' 不合法
--- 包名注入守卫 ---
  FAIL dry_run  包名 'nginx; rm -rf /' 不合法
```

**"可逆：否 —— 做下去就回不来"后面没有 apply**，这就是这道闸门存在的意义
在终端里的样子：一个不可逆的动作，在没有任何人明确点头之前，一步都没有走。

### 这次验收抓到的三个真 bug（都已修，都已进测试）

这一轮的教训值得单列，因为它改变了做法：**不只看"验收通过"，逐行读输出。**

1. **可逆性被静默污染（最严重）。** `dispatch` 里用了
   `setdefault("reversible", fn.reversible)`，而 `ok()` 的默认参数恰好是
   `reversible=True` —— 于是**任何**返回 `ok(...)` 却没显式传 reversible 的
   handler，dry_run 都会被报成"可逆"。上一轮验收里 `user.add` 就报的是
   "可逆：是"，而 `autonomicctl actions` 显示"不可逆"（对的）——
   **只看那一行永远发现不了**。后果不是显示错误：两级授权拦截不触发，
   一个不可逆的动作可以被一句 `--yes` 带过。
   修法：可逆性只声明一次（`@register`），`dispatch` 收口强制覆盖所有返回路径。
   **一个性质若在两处被声明，副本迟早撒谎。**

2. **`user.add` 的"已存在就早返回"把 verify 变成空操作。** 那句早返回写在
   三个阶段前面，于是 verify 一看"用户存在"就报成功 —— 从没检查建出来的
   用户 shell 对不对。verify 的全部价值是"去现场把 apply 承诺的每一项再数
   一遍"，提前返回等于自己把这一步废掉。

3. **`pwd` 只有 POSIX 有** → user.add 在非 Linux 上永远只会撞
   ModuleNotFoundError，正常路径一次都测不到。抽出 `_passwd_lookup()`
   之后，任何系统上都能走一遍它该走的路。

**三个都是测试抓出来的，不是看出来的。**

## 5. 刻意不做

- **不做 `apt-get upgrade` / `dist-upgrade`。** 一次全量升级跨越的版本太多，
  "预演"给不出有意义的答案，出了事也说不清是哪一步引起的。要升级就点名升级。
- **不做 `user.del`。** 它是真不可逆里最难解释的一个 —— 删了用户，UID 可能
  已经被写进别处的配置，家目录可能还挂着在跑的服务。没有一套可靠的"删用户前检查"
  之前，宁可先不做。**宁缺毋滥，缺了就明说缺。**
- **不做 `user.modify`（改组、改 shell）** —— 理由同上，等 `user.del` 想清楚一起做。
- **不做版本指定、不做第三方源。** 装什么由系统配置的仓库决定，不由提议者决定。
- **不给任何原语加"自定义参数"逃生口。**

## 6. 下一步

- `network.set` —— 网络配置（IP / 网关 / DNS），需要先把"改错网络会把自己锁在外面"
  这件事想清楚，可能得有个"改完 N 秒内不确认就自动回滚"的机制。
- `disk.*` —— 分区 / 挂载 / 文件系统。不可逆，且是**唯一一个可能让机器再也起不来**
  的类别，必须在能自动回到上一步之前不做。
- `user.del` / `user.modify` —— 见上。
- 一个 `plan` 的"历史 replay"：`/var/lib/autonomic/plans/` 现在只是留痕，
  但每份都记录了 steps 和 results，理论上可以支持"把那份计划再跑一遍"或
  "把那份计划反向跑一遍"。先不急着做，但数据结构已经为它留好了。
