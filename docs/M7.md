# M7 · 从"能执行"到"能理解"

> 状态：**✅ 已交付（2026-10-11）**
> 上游：M4（凭据）给了它思维，M5（Action 通道）给了它手脚
> 缺的正是这一层：**把思维接上手脚的那段神经**

---

## 0. M7 只做一件事

**`autonomicctl ask "……"`：说人话进，受校验的动作出。**

M5 结束时系统已经是这个状态：

```
一句话 ──✗──> ？──✗──> 通道 ──> 系统
```

通道在、能思考在，但中间那一格是空的 —— 没有任何东西把模型的话翻译成
通道能接受的动作。M7 补上这一格：

```
一句话 ──> 模型（提议）──> 校验 ──> 预演 ──> 人点头 ──> 通道（裁决）──> 系统
```

---

## 1. 一句话概括这条链路的纪律

**模型提议，通道裁决。**

模型能做且只能做「提议一串动作」。它碰不到执行入口（`dispatch` 在 actd 里，
不在它那儿），也决定不了 phase（`dry_run / apply / verify` 由 `autonomicctl`
选，不是它的参数）。

这不是不信任它，而是：**一个被猜错意图的计划和一个恶意的计划，在后果上没有区别。**
所以二者走同一道闸门。

## 3. 三道闸门

模型输出在碰到系统之前，要连过三关。

**第一关 · 结构校验（`extract_json`）**

模型喜欢把 JSON 裹在 ```` ```json ```` 里，也喜欢在前面加两句客套 —— 两种情况都真实
发生过。所以不能直接 `json.loads` 整段，而要"从第一个 `{` 开始做括号配平"。

配平时必须跳过字符串内部的括号，否则一句 `content = "{ }"` 就能把对象提前截断。
截断的 JSON **判失败，而不是被猜出来** —— 猜是这里最危险的动作。

**第二关 · 语义校验（`validate`）**

- action 必须在**真实清单**里（清单从 actd 实时取，不在代码里抄一份）
- 参数必须在 schema 里 —— 未知参数直接拒绝，它不是"多余"，要么是拼错，
  要么是模型在试着喂它想要但清单里没有的东西
- 路径必须落在可写前缀里
- **每一步必须有 reason**

校验是"整份通过或整份退回"，不存在"部分合格"。errors 非空时 steps 必为空。

**第三关 · 全计划预演**

```
for step in steps:  dry_run(step)      # 全部跑完
if 任何一步失败:     整份作废，一步都不 apply
```

**顺序是硬要求。** 允许"第 1 步成功、第 3 步被拒"这种半成品结果，等于主动制造一个
既不是目的地也不是出发点的机器 —— 而这比整个拒绝糟糕得多。

## 4. 回滚：把"可逆"从声明变成事实

这是 M7 顺手补上的一个真实漏洞。

M5 里 `reversible=True` 只是一个**声明**：`file.write` 每次 apply 都存了备份，
但没有任何机制把备份放回原位。那等于给你降落伞，不给你拉环。

补上的东西：

- 备份名带**微秒** —— 原来只到秒，同一秒内对同一文件连写两次，第二次会静默覆盖
  第一次的备份，也就是把"上一版"弄丢。回滚从来都是为了回到上一个状态，
  备份之间互相覆盖等于没备份。
- 备份旁边写一个 `.json` sidecar，记下**它原本属于哪里**。
  名字里的 `/` 被编码成 `_`，而 Linux 路径本身允许 `_`，
  所以 `etc_autonomic_my_conf` 到底指哪条路径谁也分不清。
  **猜一个文件从哪来，正是"回滚"变成"覆盖"的方式。**
  机器要还原，就必须读 sidecar；没有 sidecar 就拒绝还原。
- 新原语 `file.restore`：两端都卡死（源必须在备份目录里、目标必须在可写前缀里）。
  只卡一头的话，攻击者可以把"备份"指向任意文件再让它还原到别处。
- 还原本身**也要先备份现状** —— 回滚不是单行道，回滚错了还得能再回滚。

## 5. 留痕

每次 `ask` 都落一个 `/var/lib/autonomic/plans/plan-<时间>.json`，里面有：

```
request      用户说了什么
model        用的是哪个模型
steps        校验通过的计划（含每步的 reason）
results      每一步 apply 和 verify 的原始返回
model_raw    模型的原话（哪怕计划被拒也要留）
elapsed      思考耗时
```

审计不是给合规部门看的，是给三个月后那个半夜被叫起来的人看的：
**它当时被问了什么、说了什么、我们据此做了什么**，三样必须能放在一起读。

## 6. 验收：不花一分钱

这条链路最贵的东西不是 LLM 的智力，而是**"你确实按纪律做了"**。这些性质跟对面是
真 GPT 还是假服务毫无关系，所以用一个返回固定字节的本地假端点就能把它们全部验一遍，
而且可以重复上千遍。

```
scripts/test-plan.py    21 项  解析 / 校验 / 提示词边界
scripts/mock-llm.py      6 模式 good / empty / illegal / badstep / notjson / fence
```

测出来的两个真问题（都是这轮修的）：

1. **`os.path.normpath` 在 Windows 上把 `/etc/a` 变成 `\etc\a`**，
   于是所有合法路径都被判成"不是绝对路径"。这些路径描述的是目标 Linux 文件系统的
   语义，跟这段代码此刻跑在什么系统上无关 —— 改用 `posixpath`。
   这个 bug 只在非 Linux 上跑测试时才会暴露，正好说明为什么测试要能到处跑。
2. **mock 只认无 `/v1` 前缀的路径**，而 setup 的提示按通行写法给的是带 `/v1` 的
   地址。两边都对，所以改为两种都接。

## 7. 刻意不做

- **不给 shell 逃生口。** 不做"内置动作不够就用 shell 兜底"。缺能力就承认缺、
  加原语；一旦开了这个口子，上面三道闸门全部退化成装饰。
- **不让模型决定 phase。** `apply` 是我们调用的，不是它请求的。
- **不做多轮自主循环。** 一次 ask = 一个计划 = 一次人工点头。自主循环需要
  "怎么在没有人点头的情况下判断这件事该不该做"这个问题的答案，而它现在没有。
- **不因为"模型很聪明"而放松校验。** 校验挡的是后果，不是意图。

---

## 8. 下一步

原语只有 5 个（`file.write` / `file.restore` / `service.set` / `sysctl.set` /
`self.test`）。离"AI 掌握全部底层"最近的一段路，是**加原语**，而不是加权力：

- `pkg.install` / `pkg.remove` —— 软件包
- `user.add` / `user.modify` —— 账户（真正需要"不可逆 + 二次授权"的场景）
- `network.set` —— 网络配置
- `disk.*` —— 分区/挂载（不可逆，得配显式开关）

每加一个原语，可写范围就明确一次；不加水不加面，是这套设计能保持可信的方式。
