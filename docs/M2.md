**这就是"可以安装在计算机里、且原生支持 Agent"的第一版实物。**

## 0. M2 只做一件事

**把"一个能装的包"变成"一个能装在计算机里的系统"。**

M1 证明了 Agent 能在**别人的**系统里有身份；M2 让它变成**我们的**系统的默认值 ——
开机就在，不是装完之后才配上去的。

---

## 1. 为什么是这个顺序

CHARTER §6：仓库 → 包 → **ISO**。先做 ISO 的人最后都卡在打包上。
M1 把打包做完了，现在才轮到镜像。

---

## 2. 交付物

| # | 交付物 | 位置 |
|---|---|---|
| 1 | **根文件系统**：上游骨头 + 我们的默认值 | `build/build-rootfs.sh` |
| 2 | **可启动 ISO**：squashfs + live-boot + grub-mkrescue，BIOS/UEFI 双启 | `build/make-iso.sh` |
| 3 | 启动验证：开机 Agent 已经是系统角色 | `scripts/boot-test.sh`（VirtualBox） |

> **为什么是 ISO 而不是"磁盘镜像 + 自己装 GRUB"**：WSL 的内核虽然编译进了
> `CONFIG_BLK_DEV_LOOP`，但微软把它挡在 ioctl 之外 —— `losetup` 设不上设备
> （报 `failed to set up loop device`）。磁盘镜像那条路必须要有 loop。
> ISO 不需要：走的是所有 Debian Live 都走的路（squashfs + live-boot + grub-mkrescue），
> 全程不碰块设备，还顺便复用了上游成熟的 live 引导机制。

### 骨头全部来自上游（一行都不自己写）

内核 `linux-image-generic` · init `systemd` · C 库 glibc · 包管理 `apt` ·
构建工具 `mmdebstrap`（Debian/Ubuntu 官方）· 引导 `grub`。

### 我们只加三样（这就是"默认值"）

| 我们加的 | 为什么它算默认值 |
|---|---|
| 仓库公钥进 `/etc/apt/keyrings` + 自己的 `sources.list` | 装机后 `apt upgrade` 走**我们的**仓库 |
| `autonomic-agent` 预装且 `systemctl enable` | 开机 Agent 就在，不是"装完自己配" |
| `/etc/os-release` 写 `Autonomic OS` | 系统自报家门 |

外加 prototype 便利默认值：hostname `autonomic`、systemd-networkd DHCP、
一个可登录用户、SSH 口令登录（**装机后第一件事是改口令**）。

## 3. 验收标准

- [ ] 镜像能在 VirtualBox 里启动（EFI / BIOS 均可）
- [ ] `cat /etc/os-release` → `Autonomic OS`
- [ ] 开机即 `systemctl status autonomic-agent` **绿**（无需人工干预）
- [ ] `autonomicctl status` 显示完整身份（uid / cgroup / journal / world）
- [ ] `apt update` 走自己的仓库（签名被接受）
- [ ] 有网络（DHCP）

---

## 4. 明确不做

- ❌ 不自己做安装器（不做图形安装、不做分区工具）—— 本版用磁盘镜像 `dd` 装机
- ❌ 不改内核 / init / C 库
- ❌ 不做桌面环境（server 形态，够演示"Agent 是系统器官"）
- ❌ 不做多架构

---

## 5. 已知取舍

**为什么是磁盘镜像而不是 ISO + 安装器？**
因为"能装在计算机里"这件事，`dd` 到磁盘/U 盘就已经成立，且比先造一个安装器可靠得多。
安装器（把系统写进磁盘的那套交互）是**独立的一层复杂度**，留到 M3 —— 那时它面对的
是一个已经被验证能启动的系统，而不是一堆待定的参数。
